# brainstorming

**触发时机**：开始任何创意工作——创建功能、构建组件、添加新功能。在写代码之前。

**硬关卡**：不完成设计文档，绝不允许写代码。

## 做什么

1. 探索项目上下文——check 文件、docs、git 历史
2. 一次一个问题，逐步深入了解需求和约束
3. 提出 2-3 种方案，含 trade-off 和推荐
4. 逐段呈现设计，获取用户确认
5. 产出完整规格文档
6. 过渡到 writing-plans 进行实现规划

## 关键原则

- YAGNI 严格执行：从所有设计中移除不必要功能
- 每个项目都走这个流程——没有"太简单不需要设计"
- 设计文档放在 `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`
