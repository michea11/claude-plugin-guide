# writing-plans

**触发时机**：spec 批准后，开始实现之前。

## 做什么

1. 检查 spec 范围——是否需要拆分为多个独立计划
2. 设计文件结构——每个文件的职责和边界
3. 分解为 2-5 分钟可完成的微小任务
4. 每个任务包含：精确文件路径、完整代码、测试、预期结果
5. 零占位符：无 TBD、TODO、"implement later"

## 输出格式

每个任务包含：
- File paths（精确到行号）
- Steps（checkbox 格式）
- 实际代码（不是描述）
- 精确命令和预期输出

## 关键原则

- 假设实施者零上下文、零品味
- TDD 每步：先写失败测试 → 写实现 → 验证通过 → 提交
