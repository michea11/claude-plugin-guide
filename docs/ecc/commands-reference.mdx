## 核心工作流命令（6）

### /plan — 需求规划

```bash
/plan 给博客添加全文搜索，支持标题和内容搜索，分页显示
```

Planner agent 分析现有代码，理解项目模式，输出包含文件清单、接口设计、实现步骤的计划。

:::tip[实战]
需求越具体，规划越准。避免"做一个系统"这种模糊描述。复杂需求用 `/multi-plan`。
:::

### /tdd — 测试驱动

```bash
/tdd search.service
```

强制执行：**RED**（失败测试）→ **GREEN**（最小实现）→ **REFACTOR**（优化结构）。

:::warning[硬关卡]
会先运行测试确认失败。跳过测试直接写实现会被 tdd-guide agent 拦截。
:::

### /code-review — 代码审查

审查最近变更的质量、安全性、模式一致性。派发 code-reviewer agent。

语言专用：`/python-review` `/go-review` `/kotlin-review` `/rust-review` `/cpp-review`

### /build-fix — 构建修复

分析构建日志，分组同类错误，以最小 diff 逐个修复，不做大范围重构。

语言专用：`/go-build` `/rust-build` `/cpp-build` `/kotlin-build` `/flutter-build` `/gradle-build`

### /verify — 实现验证

验证所有需求是否实现、测试是否通过、构建是否成功。

### /quality-gate — 质量门禁

运行完整质量 pipeline：lint → typecheck → test → security → build。

## 测试命令（7）

### /e2e — 端到端测试

Playwright 自动化测试。支持生成、维护、运行 E2E 测试，管理截图/视频/Trace 产物。

### /test-coverage — 覆盖率分析

分析测试覆盖率缺口，识别未覆盖的关键路径，生成补充测试至目标阈值（80%+）。

### 语言专项 TDD

| 命令 | Agent | 用途 |
|------|------|------|
| `/go-test` | go-build-resolver | Go 测试 + 构建验证 |
| `/kotlin-test` | kotlin-build-resolver | Kotlin 测试 (Kotest) |
| `/rust-test` | rust-build-resolver | Rust 测试 (cargo test) |
| `/cpp-test` | cpp-build-resolver | C++ 测试 (GoogleTest) |
| `/flutter-test` | dart-build-resolver | Flutter/Dart 测试 |

## 规划命令（8）

### /multi-plan — 多 Agent 并行规划

大型需求拆解后派发给多个 planner agent 并行分析，最终合并方案。

```bash
/multi-plan 实现用户认证、权限管理、审计日志三个模块
```

### /multi-workflow — 多 Agent 并行开发

启动完整的多 agent 开发工作流：research → plan → execute → optimize。

### /multi-backend / /multi-frontend

按领域限定工作流范围。后端专注 API/Data/Business Logic，前端专注 Components/Layout/Animation。

### /plan-orchestrate — 计划编排

读取已有计划文档，自动拆解步骤，为每步选择最佳 agent，编排执行链。

### /prp-plan / /prp-implement

PRP (Plan-Review-Prototype) 方式：先写 PRD → 评审 → 再规划/实现。

## 会话管理命令（6）

### /save-session — 保存会话

保存当前会话至 `~/.claude/session-data/`，含完整上下文，可跨天恢复。

### /resume-session — 恢复会话

从最新存档加载，恢复中断的工作。

### /checkpoint — 创建检查点

在关键节点创建验证检查点。失败时可回溯，不用从头重做。

### /sessions — 会话管理

管理会话列表、设置别名、查看元数据。

### /aside — 旁路提问

快速提问不丢失主任务上下文。"帮我查下这个 API 的用法"。

### /context-budget — 上下文审计

分析当前 token 使用分布：agents、skills、MCP、rules 各自的消耗。

## 学习与进化命令（9）

### /learn — 提取模式

从当前会话中提取可复用的编码模式，保存为 "instinct"（本能），跨会话持久。

### /learn-eval — 评估学习

自评估提取质量：这条 instinct 是否值得保存？是否通用？

### /evolve — 进化为 Skill

分析多个 instincts，建议进化为结构化 SKILL.md。

### /skill-create — 从 Git 历史创建

分析项目的 git 历史（commit message + code diff），提取编码模式自动生成 SKILL.md。

### /skill-health — Skill 监控

Skill 组合的健康仪表盘：使用频率、冲突检测、覆盖缺口。

### /instinct-status / /instinct-export / /instinct-import

管理已学习的 instincts：查看状态、导出备份、导入恢复。

### /promote — 提升 Scope

将项目级别的 instinct 提升为全局可用。
