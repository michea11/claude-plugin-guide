## 核心工作流命令详解

### /plan — 需求规划

规划是一切的第一步。输入自然语言需求，planner agent 输出结构化实现计划。

```bash
/plan 给博客添加全文搜索功能，支持标题和内容搜索，分页显示结果
```

Planner 会分析现有代码，输出包含文件清单、接口设计、实现步骤的计划。

:::tip[实战建议]
需求复杂时用 `/multi-plan` 派多个 agent 并行规划，效率更高。
:::

### /tdd — 测试驱动开发

强制 TDD 流程：**RED → GREEN → REFACTOR**。

```bash
/tdd search.service
```

1. **RED**：生成失败的测试用例
2. **GREEN**：生成刚好通过的最小实现
3. **REFACTOR**：在测试保护下优化代码

:::warning[注意]
tdd-guide agent 会在实现前检查测试是否真的失败。跳过测试直接写实现会被拦截。
:::

### /code-review — 代码审查

审查最近变更。也可以指定语言专用审查：

```bash
# 通用审查
/code-review

# 语言专用
/python-review
/go-review
/kotlin-review
```

Code reviewer 检查：代码质量、安全隐患、边界条件、是否遵循项目模式。

### /build-fix — 构建修复

```bash
/build-fix
```

Build error resolver 分析错误日志，以**最小 diff** 逐个修复。语言专用：

```bash
/go-build       # Go 构建
/rust-build     # Rust 构建
/cpp-build      # C++ 构建
/kotlin-build   # Kotlin/Gradle
```

## 常用场景组合

| 场景 | 命令序列 |
|------|---------|
| 新功能开发 | `/plan` → `/tdd` → `/code-review` |
| Bug 修复 | `/tdd` → `/code-review` → `/build-fix` |
| 安全审计 | `/security-scan` |
| 多模块并行 | `/multi-workflow` |
| 重构清理 | `/refactor-clean` |
| 学习归档 | `/learn` → `/learn-eval` → `/evolve` |

:::info[更多命令]
完整命令列表在 ECC 插件目录 `commands/` 下。每个命令的 `.md` 文件包含了完整的行为定义。
:::
